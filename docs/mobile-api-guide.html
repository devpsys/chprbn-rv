Mobile API developer guide

This guide documents the centre mobile API used for attendance, practical marking, and project assessment. Authenticate with the centre api_key in the X-Location header, pull today’s schedule pack, then push results.

Base path /api/v1/mobile Auth X-Location: <api_key> Schedules include start_time / end_time Actor centres table JSON envelope status / message / data
1. Authenticate Send X-Location with the centre API key
2. Sync day pack Fetch schedules (date + times), candidates, PE sections
3. Push results Attendance, project, and practical scores

Quick start

  1. Configure the centre api_key on the client (from centre setup / admin).
  2. On every request, send header X-Location: <centre.api_key>. Query ?api_key=… is an optional fallback. There is no login endpoint.
  3. Call /attendance/fetch-record to download today’s candidates and mark sheets.
  4. Push attendance, project, and/or practical scores with the endpoints below.

Response envelope

Most endpoints return this JSON shape (helper jResponse):

Example
{
  "status": true,
  "message": "Successful",
  "data": {}
}
status is a boolean. Treat HTTP 401 as “missing or invalid X-Location”. Some older failure paths may omit the data key.

Authentication rules

Item Detail
Credential Centre api_key (no Sanctum / Bearer token, no login)
Required header X-Location: <centres.api_key>
Fallback Query or JSON/form field api_key (optional)
Middleware mobile.centre → EnsureMobileCentreApiKey
Login endpoint Removed — POST /api/v1/mobile/login is not registered
Required header example
X-Location: mchst213
Do not send Authorization: Bearer …. The middleware reads X-Location (preferred) or api_key from query/body.

1. Centre profile

GET /api/v1/mobile/centre X-Location required Live

Returns a trimmed profile for the authenticated centre.

Success response
{
  "status": true,
  "message": "successful",
  "data": {
    "name": "Federal College of Health",
    "location": "Lagos",
    "username": "mchst213",
    "status": "Active"
  }
}
cURL example
curl "https://YOUR-HOST/api/v1/mobile/centre" \
  -H "Accept: application/json" \
  -H "X-Location: mchst213"

4. Fetch today’s examiner pack

GET | POST /api/v1/mobile/attendance/fetch-record X-Location required Live

Downloads today’s schedules for venues belonging to the authenticated centre, including schedule window times, candidates (with base64 passport photos), paper assignments, and practical sections when a PE paper is present.

Practical mark sheets (sections) are included only when at least one resolved paper has code PE. Orphaned assignment subject_id values are remapped via test_subjects for the schedule’s test config so candidates and papers still return.

5. Push attendance

GET | POST /api/v1/mobile/attendance/push-record X-Location required Live

Upserts attendance rows. Body is an object with an attendances array and a mandatory assessor block. Unique key: (scheduled_candidate_id, paper_id, year).

Request body
{
  "attendances": [
    {
      "scheduled_candidate_id": 501,
      "schedule_id": 45,
      "candidate_id": 101,
      "paper_id": 8,
      "sign_in": 1,
      "sign_out": 0,
      "remark": "AE",
      "year": 2026
    }
  ],
  "assessor": {
    "id": 12,
    "name": "Jane Field Officer",
    "email": "jane.field@example.com",
    "phone": "08012345678",
    "username": "jane.field",
    "status": 1,
    "department": "ACC",
    "location": "Lagos",
    "roles": ["Inspector", "Verify Practitioners"]
  }
}
FieldTypeNotes
attendances[].scheduled_candidate_idintFrom fetch-record → paper_candidates[].scheduled_candidate_id
attendances[].schedule_idintFrom fetch-record → schedules[].id
attendances[].candidate_idintFrom candidates[].id / paper_candidates[].candidate_id
attendances[].paper_idintFrom paper_candidates[].paper_id / papers[].id
attendances[].sign_in / sign_outintUsually 0 or 1 (map client statuses like signed_out to these)
attendances[].remarkstring\|nullPrefer a code from attendance remarks (e.g. AE)
attendances[].yearintPrefer data.year from the fetch pack
assessorobjectSee Assessor block — same shape for all three push endpoints. Required.
Do not send { "items": [...] }, a bare top-level array, status, client_id, or marked_at. Those shapes cause failures such as Attempt to read property "candidate_id" on array. Omitting assessor returns Assessor is required. Include an "assessor" object with id and username.
Success response
{
  "status": true,
  "message": "Successful",
  "data": [101]
}
Success data is the list of candidate_id values from the payload.
cURL example
curl -X POST "https://YOUR-HOST/api/v1/mobile/attendance/push-record" \
  -H "Accept: application/json" \
  -H "X-Location: mchst213" \
  -H "Content-Type: application/json" \
  -d '{
    "attendances":[{"scheduled_candidate_id":501,"schedule_id":45,"candidate_id":101,"paper_id":8,"sign_in":1,"sign_out":0,"remark":null,"year":2026}],
    "assessor":{"id":12,"username":"jane.field","name":"Jane Field Officer","email":"jane.field@example.com","phone":"08012345678","status":1,"department":"ACC","location":"Lagos","roles":["Inspector"]}
  }'

Identifies the logged-in field officer submitting the batch. The same shape is required on attendance/push-record, project/push-record, and practical/push-record. Missing it returns the exact envelope:

  "data": "Assessor is required. Include an \"assessor\" object with id and username." }

Errors & integration tips

Common issues

SymptomLikely cause
HTTP 401 on protected routes Missing or invalid X-Location header (or fallback api_key)
Empty schedules No schedule dated today for this centre’s venues
Empty candidates / papers No assignments for today, or orphaned subject ids without matching test_subjects
Empty sections No PE paper on today’s schedule, or no active practical questions seeded
Attempt to read property "candidate_id" on array Attendance push body sent as a bare array or wrapped as { "items": [...] } instead of the { "attendances": [...], "assessor": {...} } object
Assessor is required. Include an "assessor" object with id and username. Push body missing the assessor block (all three push-record endpoints — attendance, project, practical). See Assessor block.
Practical scores not saving Sending array instead of object, missing the assessor block, or using practical_question_id instead of question_id
Recommended client flow
1) GET  /attendance-remarks     (X-Location)
2) GET  /adhoc/profile          → cache assessor identity (id, username, name, …)
3) POST /attendance/fetch-record  → keep schedule id, times, paper_candidates, year
4) POST /attendance/push-record   → { "attendances": [...], "assessor": {...} }
5) POST /practical/push-record    → { "practicals": [...], "projects": [...], "assessor": {...} }
   POST /project/push-record      → { "projects": [...], "assessor": {...} }
